## Common 模块：using prevent（custom_data 使用限制）

- 需求：配置 `using-prevent.custom-data` 命中任意一项的物品，禁止放进工作方块、禁止参与合成。
- **custom_data 读取口径（关键）**：Paper 1.21.8 的 `DataComponentTypes` **没有** `CUSTOM_DATA`；纯 Paper 只能通过 `ItemStack#getPersistentDataContainer()`（`PersistentDataContainerView`）读 `custom_data.PublicBukkitValues`。**现已迁移到 Item-NBT-API**，可读顶层键，详见下方「迁移」段。
- 匹配写法：`streack:protected` 精确匹配；`protected` 按 key 名匹配任意命名空间；`PublicBukkitValues.` / `custom_data.PublicBukkitValues.` 前缀自动剥除。
- 新建 `Common/UsingPreventListener.java`：
  · 工作方块白名单 = FURNACE/BLAST_FURNACE/SMOKER/BREWING/STONECUTTER/CARTOGRAPHY/ANVIL/GRINDSTONE/LOOM/SMITHING/ENCHANTING/BEACON/CRAFTER/LECTERN/WORKBENCH/CRAFTING；**不含** CHEST/BARREL/SHULKER_BOX/ENDER_CHEST/HOPPER/DROPPER/DISPENSER（存储不算「使用」）
  · `InventoryClickEvent`：顶部非 RESULT 槽 ← cursor / 数字键 hotbar / 副手；底部 Shift ← currentItem（排除 CRAFTING/WORKBENCH，且顶部须有非 RESULT 空槽，避免误伤背包整理）
  · `InventoryDragEvent`：旧 cursor 受限 + rawSlots 命中顶部非 RESULT
  · `PrepareItemCraftEvent` → `setResult(null)` + `CraftItemEvent` → cancel（`getMatrix()` 含受限物品）
  · `InventoryMoveItemEvent`：destination 是工作方块且 item 受限 → cancel（堵漏斗/投掷器自动输入）
- ⚠️ `InventoryType.SMITHING_NEW` 在 1.21.8 已 `@Deprecated(forRemoval)`；`SMITHING` 本身就是 4 槽新锻造台（3 CRAFTING + 1 RESULT），只用 SMITHING。
- `InventoryView#getSlotType(int)` 用于按槽判断 RESULT，比硬编码槽位号可靠。
- 配置模板 `src/main/resources/models/Common.yml` 与 `mcserver/plugins/Joyous/models/Common.yml`（后者未进 git）同步加了 `using-prevent` 段；`requireFileAndCheck(..., null)` 对已存在文件**不覆盖**，故代码里全部用 `getBoolean/getListOfString(key, default)` 兜底。

## Common 模块：custom_data 迁移到 Item-NBT-API

- 依赖：`de.tr7zw:item-nbt-api-plugin:2.16.1`（provided）。⚠️ 包名是 `de.tr7zw.nbtapi`（**不是** `de.tr7zw.changeme.nbtapi`，那是重定位发行版）；该 jar 的 `de/tr7zw/nbtapi/` 已含完整 API（NBT / ReadableNBT / iface / handler / wrapper）。
- 关键 API 事实（2.16.1，wiki 确认）：1.20.5+ 起 `NBT.get(ItemStack, Function<ReadableItemNBT,T>)` **只访问 `custom_data` 组件**（不再是旧 `tag`）；要读完整组件用 `NBT.getComponents(...)`。`NBT.itemStackToNBT` 得到的是 `{components:{"minecraft:custom_data":{...}},count,id}`。
- 新增 `limiter/NbtCustomData.java`（隔离层）：`getPlugin("NBTAPI")` + `Class.forName("de.tr7zw.nbtapi.NBT")` 双重检测 → `AVAILABLE`；`keys(stack)` = `nbt.getKeys()`（顶层）+ `nbt.getCompound("PublicBukkitValues").getKeys()`；不可用/异常返回 `null`。
- `UsingPreventListener`：`presentKeys()` 优先 NBT、`null` 回退 PDC；键统一 lowercase 后按 `namespace:key` 比较；`hit()` 对无命名空间 token 按本地键名宽松匹配；`normalize()` 末尾 lowercase。
- ⚠️ **必须隔离引用**：NBTAPI 缺席时 classpath 没有 `de.tr7zw.nbtapi.*`，监听器里直接引用会在类解析阶段抛 `NoClassDefFoundError`，拖垮整个 `registerEvents`。所以 `NbtCustomData` 用全限定名 + try/catch，`plugin.yml` 用 **softdepend** 而非 depend（硬 depend 会让未装 NBTAPI 的服务器整个插件加载失败）。
- `plugin.yml` 的 `softdepend` 已含 `NBTAPI`（用户已提交 914ce5e）；测试服已放入 `mcserver/plugins/item-nbt-api-plugin-2.16.1.jar`。
- 启动日志：`CommonMain.onEnable` 打印 `custom_data 读取模式：Item-NBT-API / PDC 回退`。
- ⚠️ 待办：配置里新增的 `invcraft-limiter: true` 目前**没有被 `InvCraftListener` 读取**（开关未接线）。
