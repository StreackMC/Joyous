## 三模块「聊天栏输入 + 容器 UI」重复实现盘点（只读，未改 src/main/**）

用户要求先出合并方案。核对结论：

- **JMenu 没有聊天栏输入**（全仓库只有 `WardListener` / `JSellListener` 监听 `AsyncChatEvent`），
  JMenu 只有容器 UI。真实重复是：聊天输入 2 份（Ward/JSell），容器 UI 3 份。
- 聊天输入 2 份几乎逐行同构：`Map<UUID,Pending>` + TTL + 「先登记再 closeInventory」+
  `isWaiting/hasPending/submit/clear` + `runOnMain` + 提示（prompt/点击填入旧值/cancel 提示）。
  差异只在：i18n 前缀、字段标签来源、额外 hint、`unset` 特殊词、accept 异常兜底、`bind(editor)` 循环依赖。
- 容器 UI 三份各自造了：`Holder implements InventoryHolder`（Ward/JSell 各一份，JMenu 用 **null holder
  + ACTIVE_MENUS** 反查）、`holderOf`、`legacy()`+ensureReset（三份：WardGui/JSellGui/JMenuEntry）、
  `button/filler/title`、以及各自的 onClick/onDrag/onClose 路由。
- 三家取消策略不同：JMenu 全取消（连玩家背包点击也取消），Ward 只拦上半区+shift/double，
  JSell 按 kind 分别处理 → 共享层的 onClick 必须返回三态而不是 boolean。
- 超时配置也是两份：`jwardchest.session.chat-input-timeout` / `jsell.command.chat-input-timeout`。
- 语言键两套：`jwardchest.input.*`(16) / `jsell.input.*`(20)，chrome 部分重复。

方案要点（详见对话）：新增 `com.github.streackmc.Joyous.ui.{gui,chat}` 两包，
只收「识别/路由/生命周期/输入机制」，**不收布局与语义**；`Screen` 接口 + `GuiHolder`（取代 Kind 枚举
与 ACTIVE_MENUS）+ `ClickResult{HANDLED,CANCEL_ONLY,ALLOW}` + `GuiManager`（reopenLater/repaint/isOurs）
+ `ChatInput`（链式 onAccept/onAlias/onFinish，内部写死「先登记再关界面」与「回主线程」）。
迁移顺序：JMenu（试点，最简单）→ ChatInput+Ward → JSell → 删旧件 → 语言/config 收敛。

## JSell 细节优化：玩家视角限售提示 + `/sellset <单价> [物品ID]`

1. **限售提示改成玩家语言**：原来画的是配置原样「限售：64 个 / 86400 秒」，玩家看不出
   「现在还能卖几个、什么时候能再卖」。改为按当前玩家的真实用量算：
   「还可卖出 12 个，限额将于 23 小时 59 分钟后重置」；卖满 → 「本期已达上限，限额将于 … 后重置」；
   终身累计（`limitSeconds<=0`）不出现「重置」；不限量（`limitCount<=0`）整行不出现。
   - 重置时间取 **MAX(sold_at) + 窗口**：窗口是滚动的（只看最近 N 秒），要等最后一次卖出过期
     额度才恢复满额。新增 `SellStore.usage()` 一次查出 `SUM(amount)` 与 `MAX(sold_at)`。
   - 时间只到分钟：> 24h 写「约 N 天」（四舍五入），否则「N 小时 M 分钟 / M 分钟 / 不足 1 分钟」。
     不写秒是刻意的 —— 这行画在 Lore 里，秒级跳动只会让每帧看起来都变了。
   - 额度查询按条目缓存（一次绘制一份 `Map<UUID,Quota>`），45 格同物品只查一次库。

2. **`/sellset <单价> [物品ID]`**：省略物品 = 主手（`hand`），也可写材质键（`diamond_sword`、
   `minecraft:diamond_sword`，带补全，上限 64 条候选）。已有条目就改价，没有就用这件物品登记一条
   （主手会连 NBT 一起存），随后**直接打开该条目的编辑页**。用 `findIncludingRemoved` 匹配，
   避免「对已移除的条目再设一次价」时又建出一条重复项（已移除状态保持不变并给一句提示）。

验证：临时自检（验完已删）12/12 通过 —— 7 条时间文案逐条核对（23h59m / 25h / 3d / 3h / 40s /
窗口 86400s / 0），以及 `usage()` 的 SUM、MAX、窗口 `>=` 过滤、`pruneUsage` 归零；
另用控制台跑 `sellset 10`、`sellset 10 diamond_sword` 确认参数节点能解析（控制台回「只能由玩家执行」）。
