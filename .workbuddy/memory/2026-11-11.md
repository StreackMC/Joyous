## 核对 StreackLib 的 SConfig 嵌套路径缺陷（master@9dac922）

用户要求核对 GitHub 最新 HEAD。方法与结论：

- 拉 `raw.githubusercontent.com/.../master/.../SConfig.java`（2831 行），
  并读 `9dac922` 提交元信息：**2026-10-14，Neonai，就是 master 的 HEAD**。
  提交信息自述根因与修法，和我 11-09 独立复现的一致（`getIndexOfNormalDot` 返回第一个点，
  `putNested`/`remove` 却按最后一个点取叶子键）。
- master 改法：删掉对外暴露下标的方法 → `hasNestedPath()`（只回答有没有嵌套）；
  `splitWithNormalDot()` 成为读/写/删/`isReachable`/Properties 后端的**唯一分段权威**；
  `putNested`/`remove` 取 `parts.get(size-1)` 作叶子；顺带修了「转义点写得进读不出」。

### 实测（把 master 的 SConfig.java 单独编译，垫在 0.6.1 jar 前面跑同一组探针）

| 场景 | 0.6.1（线上） | master@9dac922 |
|---|---|---|
| `putString("items.<uuid>.item")` 后读回 | 写出 `items.<uuid>: { "<uuid>.item": v }`，读 `<MISS>` | 正确嵌套，读回正常 |
| `a\.b.c` 转义点 | 能写，读不回 | 写读都对 |
| `remove("items.id1.value")` | **静默无效**（删了个不存在的键） | 正确删除，兄弟保留 |
| `isReachable("items.id1.nope")` | true | true（这是「中间层能否深入」的语义，不是存在性，非 bug） |

踩坑记录：`StreackLib-0.6.1.jar` 带 BouncyCastle 签名，直接上 classpath 会
`SecurityException: Invalid signature file digest`；`zip -d jar 'META-INF/*.SF' ...` 后可用。

### 连带发现（存量问题，不是 JSell 引入的）

`i18n.tr` 在缺键时用 `currentMap.putString(key, 结果)` 做差量回写，而语言键基本都是 3 层
（`jwardchest.editor.title` / `jsell.editor.title`）→ 在 0.6.1 上全部写坏。
线上 `mcserver/plugins/Joyous/language.yml` 已积 **231** 个形如
`jsell: { editor.title: … }` 的残缺键；因为这些键读不到，管理员改的译文不生效（每次回落内置默认）。
