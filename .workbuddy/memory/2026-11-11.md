## 三模块「聊天栏输入 + 容器 UI」重复实现盘点（只读，未改 src/main/**）

用户要求先出合并方案。核对结论：

- **JMenu 没有聊天栏输入**（全仓库只有 `WardListener` / `JSellListener` 监听 `AsyncChatEvent`），
  JMenu 只有容器 UI。真实重复是：聊天输入 2 份（Ward/JSell），容器 UI 3 份。
- 聊天输入 2 份几乎逐行同构：`Map<UUID,Pending>` + TTL + 「先登记再 closeInventory」+
  `isWaiting/hasPending/submit/clear` + `runOnMain` + 提示（prompt/点击填入旧值/cancel 提示）。
  差异只在：i18n 前缀、字段标签来源、额外 hint、`unset` 特殊词、accept 异常兜底、`bind(editor)` 循环依赖。
- 容器 UI 三份各自造了：`Holder implements InventoryHolder`（Ward/JSell 各一份，JMenu 用 **null holder
  + ACTIVE_MENUS** 反查）、`holderOf`、`legacy()`+ensureReset（三份：WardGui/JSellGui/JMenuEntry）、
  `button/filler/title`、以及各自的 onClick/onDrag/onClose 路由。
- 三家取消策略不同：JMenu 全取消（连玩家背包点击也取消），Ward 只拦上半区+shift/double，
  JSell 按 kind 分别处理 → 共享层的 onClick 必须返回三态而不是 boolean。
- 超时配置也是两份：`jwardchest.session.chat-input-timeout` / `jsell.command.chat-input-timeout`。
- 语言键两套：`jwardchest.input.*`(16) / `jsell.input.*`(20)，chrome 部分重复。

方案要点（详见对话）：新增 `com.github.streackmc.Joyous.ui.{gui,chat}` 两包，
只收「识别/路由/生命周期/输入机制」，**不收布局与语义**；`Screen` 接口 + `GuiHolder`（取代 Kind 枚举
与 ACTIVE_MENUS）+ `ClickResult{HANDLED,CANCEL_ONLY,ALLOW}` + `GuiManager`（reopenLater/repaint/isOurs）
+ `ChatInput`（链式 onAccept/onAlias/onFinish，内部写死「先登记再关界面」与「回主线程」）。
迁移顺序：JMenu（试点，最简单）→ ChatInput+Ward → JSell → 删旧件 → 语言/config 收敛。

## JSell 细节优化：玩家视角限售提示 + `/sellset <单价> [物品ID]`

1. **限售提示改成玩家语言**：原来画的是配置原样「限售：64 个 / 86400 秒」，玩家看不出
   「现在还能卖几个、什么时候能再卖」。改为按当前玩家的真实用量算：
   「还可卖出 12 个，限额将于 23 小时 59 分钟后重置」；卖满 → 「本期已达上限，限额将于 … 后重置」；
   终身累计（`limitSeconds<=0`）不出现「重置」；不限量（`limitCount<=0`）整行不出现。
   - 重置时间取 **MAX(sold_at) + 窗口**：窗口是滚动的（只看最近 N 秒），要等最后一次卖出过期
     额度才恢复满额。新增 `SellStore.usage()` 一次查出 `SUM(amount)` 与 `MAX(sold_at)`。
   - 时间只到分钟：> 24h 写「约 N 天」（四舍五入），否则「N 小时 M 分钟 / M 分钟 / 不足 1 分钟」。
     不写秒是刻意的 —— 这行画在 Lore 里，秒级跳动只会让每帧看起来都变了。
   - 额度查询按条目缓存（一次绘制一份 `Map<UUID,Quota>`），45 格同物品只查一次库。

2. **`/sellset <单价> [物品ID]`**：省略物品 = 主手（`hand`），也可写材质键（`diamond_sword`、
   `minecraft:diamond_sword`，带补全，上限 64 条候选）。已有条目就改价，没有就用这件物品登记一条
   （主手会连 NBT 一起存），随后**直接打开该条目的编辑页**。用 `findIncludingRemoved` 匹配，
   避免「对已移除的条目再设一次价」时又建出一条重复项（已移除状态保持不变并给一句提示）。

验证：临时自检（验完已删）12/12 通过 —— 7 条时间文案逐条核对（23h59m / 25h / 3d / 3h / 40s /
窗口 86400s / 0），以及 `usage()` 的 SUM、MAX、窗口 `>=` 过滤、`pruneUsage` 归零；
另用控制台跑 `sellset 10`、`sellset 10 diamond_sword` 确认参数节点能解析（控制台回「只能由玩家执行」）。

## 共享交互层（JoyousInteract）设计与铁砧输入的可行性核实

用户提议：三模块（JMenu/JSell/JWardChest）的「聊天输入 + 容器 UI」合并成 Joyous 公共交互 API——
`ChatInteract` / `ChestGui<T> implements JoyousInteract` + 每玩家一个交互管理器（显示/生命周期/排队/插队/打断）。
另提议用**铁砧界面**做小编辑（数字、时间）：输入框 = 文本，取消槽 + 结果槽 = 确认。

核实结论（用 paper 1.21.11 服务端字节码实测，非推测）：

- ❌ **`Bukkit.createInventory(holder, InventoryType.ANVIL)` 的假铁砧收不到输入**：
  `CraftHumanEntity.openCustomInventory` 建的是 `CraftContainer` 并赋给 `player.containerMenu`；
  而 `ServerGamePacketListenerImpl.handleRenameItem` 只认 `containerMenu instanceof AnvilMenu` → 改名包被丢弃。
  （`CraftContainer` 内部确实 new 了 `AnvilMenu` 当 delegate，但顶层菜单不是它，instanceof 不过。）
- ✅ 要用真实铁砧菜单：`MenuType.ANVIL.builder().location(...).checkReachable(false).title(...).build(player)`
  → `openInventory(view)`。`checkReachable(false)` 对应 `AbstractContainerMenu.checkReachable=false`，
  即 `stillValid` 直接返回 true，**不需要真实铁砧方块**（`openInventory(loc,force=material)` 里 `checkReachable = !force`）。
- ⚠️ `HumanEntity#openAnvil(Location, boolean)` **自 1.21.4 起 @Deprecated**，替代品就是上面的 `MenuType.Typed#builder()`。
- ✅ 读输入用 `AnvilView#getRenameText()`（Paper API，存在且是正道），不要读结果槽物品名。
- 槽位真相：0/1 是菜单自有的 `SimpleContainer(2)`，2 是 `ResultSlot` 且**由 `createResult()` 每次重算**，
  放不了自定义「确认」图标；把图标放 1 号槽会被当成修理/合并材料参与计算（结果槽是否变空需实测）。
- 必须 `CANCEL_ALL`：`AnvilMenu.quickMoveStack` 允许玩家把背包物品 shift 进 0/1，关闭即随菜单丢弃=吞物品。
- 铁砧界面**挂不了我们的 InventoryHolder**（inventory 是 `CraftInventoryAnvil`）→ 路由不能只靠 Holder，
  要改成「每玩家栈顶 + `view.getType()` 校验」，并用 `InventoryOpenEvent` 检测「别人接管」；
  这个改动顺带能替掉 JMenu 的 `ACTIVE_MENUS`（它现在靠「先 openInventory 再 put」绕关闭事件）。
- 铁砧没有「输入事件」：只能在确认点击时读，实时校验需 1 tick 轮询。

框架结论：`TextInteract`（初值 + onInput + onCancel）作父接口，`ChatInteract` / `AnvilInteract` 只是两种 transport；
`ShowPolicy{REPLACE, PUSH, QUEUE}` + 「视图关闭 ≠ 会话终止」（`onSuspend/onResume` vs `onDetach`）是核心。
`ChestGui<T>` 的泛型无收益 → 直接提升已有的 `WardContainerType` 为 `InteractContainer`。

## 实现：页面仲裁器 utils/interact（9 个类）

按确认的规格落地 `PagePriority{INSTANT,REPLACE,NORMAL,INSERT}` + `JoyousPage.keepable()` + 每玩家队列。

- 文件：PagePriority / PageState / DetachReason / JoyousPage / PageHandle / PageContext / PageEntry /
  PlayerPages / PageArbiter。前 6 个 public，PageEntry/PlayerPages 包内可见。
- 硬规则：①当前界面立即关闭、新页延后 1 tick 显示；②同帧多条立即类按 (submittedAt,seq) 由旧到新依次应用，
  先显示的可能是 0 帧但钩子照常成对；③INSTANT 遇 keepable=false 降级为 REPLACE 并 warn
  （玩家名/uuid + 双方 key/purpose）；④去重 = 每玩家 + (key,purpose)；⑤队列上限 8、PENDING 过期 10 分钟、
  SUSPENDED 不过期；⑥单轮最多 32 次转移，超出丢弃剩余并告警；⑦转移中的新请求只入待办（防重入）。
- 纯 JVM 自检 47 项全过（临时 harness，验完已删）：attach、INSTANT 挂起/恢复、降级、REPLACE、
  NORMAL/INSERT 排序、双 REPLACE、INSTANT↔REPLACE 四种组合、两种去重口径、上限丢弃、stillValid 失效、
  clear 幂等、onDetach 内重入、互相打开的活锁保护。
- ⚠️ 自检跑法：`java -cp "target/classes:paper-api.jar:StreackLib.jar"`。StreackLib jar 必须先
  `zip -d` 掉 `META-INF/*.SF|DSA|RSA`，否则 `SecurityException: Invalid signature file digest`
  （shade 破坏了签名）；且必须带上它，因为 jlogger 的 JUL 后端用到 `StreackLib.utils.MCColor`。
- 未接线：还没有模块调用 PageArbiter，entry 里也没有 install()；首次 open 会用 `Joyous.plugin` 兜底安装。

## 实现：容器页面层 + JMenu 迁入仲裁器（I1）

- 新增（均署 @author Neonai）：`GuiInteract`（外形/标题/render/onClick）、`SimpleGuiPage`（开界面·重绘·关闭）、
  `Canvas`（legacy/title/button，收掉三份 ensureReset）、`InteractHolder`（唯一 Holder）、
  `InteractContainer`（容器外形表，不含图标/显示名）、`Click`/`ClickPolicy`（取消策略与语义分离）、
  `GuiRouter`（点击/拖拽/关闭路由）。
- `PageArbiter`：新增 `visible(Player)`、`closeAll(key,purpose)`；`install` 时一并注册 `GuiRouter`。
- `entry`：启用阶段在子模块之前 `install(this)`；停用阶段先 `shutdown()`（钩子要在模块还活着时执行）。
- JMenu：`JMenuPage` 取代 `openJavaMenu` 的建界面逻辑；删 `ACTIVE_MENUS` 与点击/拖拽/关闭/退出四个处理器，
  监听器只剩「用菜单物品打开菜单」。子菜单用 REPLACE（ESC 不退回上一级，保持原语义）；keepable=true。
- 关键判定：`InventoryCloseEvent` 里**只有 `state()==VISIBLE` 才算玩家主动退出**；切页/挂起/终止都会触发 close，
  按状态过滤掉即可（这也是原先 JMenu 用「先 openInventory 再 put」绕开的那个坑）。
- ⚠️ 1.21.8 的 `ClickType` 没有 `COLLECT_TO_CURSOR`（双手收集=DOUBLE_CLICK），编译期才发现。
- 真机冒烟（Paper 1.21.11，隔离目录，端口 25567）：全部模块启用，
  日志出现「页面仲裁器已启用：队列上限 8 条，排队过期 10 分钟」，无本模块异常。
  **未验证**：真实点击 / ESC / 子菜单跳转 / 面板重绘（需要客户端）。
