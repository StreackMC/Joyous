# 2026-10-05

## Restarter 模块审计 + 修复

### 审计手法（可复用）
- 读源码 + 读依赖库源码（`~/.m2/.../StreackLib-0.6.1-sources.jar` 里的 `SConfig`）确认 API 语义
- 用 `javap -p -c` 反编译服务端字节码取证平台行为（结论：`PaperPluginInstanceManager.disablePlugin`
  先 `setEnabled(false)`→onDisable，**之后**才 `cancelTasks(plugin)`，且 `CraftScheduler` 的
  cancelTasks 会清空 pending 队列 → onDisable 里安排的任务必死）

### 修复内容（RestarterMain.java + RestarterCommand.java + config.yml）
1. **preventInterrupt 完全失效** → 改为注册 JVM 关闭钩子（`installShutdownHook`），
   不再在 onDisable 里塞调度任务；新增 `launchRestartScript()` 直接 exec restart-script
   （刻意不用 `Server.restart()`，因为它每次都 addShutdownHook、非幂等会重复重启）。
   钩子带 `owner != Joyous.plugin` 守卫，防 PlugMan 热重载后旧钩子重复重启。
2. **计划重启被误判异常关闭** → 引入 `exitIntent` 标记（scheduleStop / performRestart /
   performShutdown 置位，`cancelPlan()` 复位）；`cancelCountdown()` **刻意不清位**
   （否则倒计时结束时先 cancel 再 performRestart 会把标记抹掉）。
3. **假人名册在踢人后才采集 → 每轮清空** → 新增 `saveStateAndKickAllPlayers()`，保存先于踢人；
   4. **命令增删假人不落盘** → `addFakePlayer/removeFakePlayer` 立即 `persistFakePlayers()`；
5. **改为「常驻名册」模型**：`recoverFakePlayers()` 恢复后不再 clear 内存与 dat ——
   名册是崩溃（onDisable 不执行）时唯一的恢复依据。
6. **checkTimeConditions 的 ClassCastException**（YAML `days: [7.2]` 是 Double、
   `dayOfM: [1]` 是 Integer）→ 全部改用 `getInt/getListOfString` 类型化访问器。
7. 时间条件语义改为「时刻字段彼此与 + 日期规则彼此或 + 日期与时刻相与 + 全空不触发」
   （原 OR 语义让默认配置变成"每分钟一次"，已在 config.yml 写明新语义）。
8. 重启脚本未配置时真正回退为关闭（原来只打日志、什么都不做）。
9. 泄漏检测：原公式在"整体上涨"前置判断下恒为负、必然触发 → 改为取窗口内
   **最后一次 Full GC 的前后采样对**计算回收率。
10. 堆转储移到独立线程 + 完成后才重启（否则 JVM 退出会留下截断的 .hprof）+ `heapDump.keep` 保留份数。
11. `matchesDayOfMonth` 正则元字符转义；`days` 用真实日历长度校验（2.30 会被忽略）；
12. `Server` 字段初始化改为 `Bukkit.getServer()`（去掉对 `Joyous.plugin` 初始化顺序的隐式依赖）。

### 未修（已说明）

- 假人名一律小写化并用于 `fp spawn %name%`（大小写敏感的命令可能匹配不上）。
- 内存检测仍被 `autoRestart.timeout >= 0` 绑住。
