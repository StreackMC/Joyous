# 2026-10-14 工作日志

## JwardChest 模块（战利品箱）新建

用户给了完整规格，新增一个模块：绑定任意方块 → 自定义容器 → 抽结果 → 搜索动画。

### 交付物（`src/main/java/.../JwardChest/`，16 个文件）
- `JwardChestMain` —— JoyousModel + 全部配置访问（`CONF`），生命周期装配与周期清理
- `WardRarity` —— 五档珍惜度（普通白/稀有绿/典藏紫/珍贵金/绝世红），带搜索时长与完成音效
- `WardContainerType` —— 12 种原版容器；只有箱子支持 1-6 行
- `WardItemEntry` —— 物品 + 权重 + 珍惜度 + 数量范围；`serialize()` 用 Base64(item):weight:rarity:min:max
- `WardProfile` —— 一个容器的完整设置（唯一 UUID + 预设代号）
- `WardProfileStore` —— SConfig+YAML 落盘 `models/JwardChest/profiles.yml`
- `WardBinding` —— 绑定关系写在**区块 PDC**（键含方块坐标），随区块存盘
- `WardGui` —— 自定义 InventoryHolder + 黑/白玻璃板占位物品（PDC 标记 `joyous:jc_placeholder`）
- `WardSession` / `WardSessionManager` —— 内存态会话（结果组共享、每玩家进度独立、带维度坐标、空闲回收+总数上限）
- `WardRoller` —— 按权重抽取，各品质上限即配额
- `WardSearchController` —— 打开 / 粗筛 / 逐格搜索动画 / 音效 / 关闭时保留进度
- `WardEditorGui` —— 7 个按钮的主编辑界面 + 容器类型/行数/各品质上限/待选物品（6 行分页）子菜单
- `WardChatInput` —— 聊天栏输入（可点击「粘贴旧值」、cancel、unset）
- `WardListener` —— 交互拦截、点击/拖拽、关闭、退出、聊天截获
- `JwardChestCommand` —— `/jwardchest`（别名 `/jc`）：new / unbind / reload / reset all|preset|radius|box

### 关键设计决策（规格留白处的取法）
- **预设组语义**：②「预设代号」就是预设组名。代号不为空 ⇒ 生效设置取预设组，且编辑写回预设组
  （所以「修改其设置会使同预设组的全部设置一并被修改」）；代号为空 ⇒ 用容器自己那份设置。
  二者是覆盖关系：容器自身设置被保留为「解绑预设后的回退」。
- **各品质最大抽出数量**＝既是上限也是配额：结果组总条数 = 各品质上限之和；
  抽取时按权重在「仍有剩余配额的珍惜度」里挑，权重 0 的条目保留但不参与抽取。
- 组的 YAML 键用 **URL 安全 Base64**（预设代号允许 `.`，而 SConfig 路径以 `.` 分隔，直接当键会串层）
- 会话键 = `维度@x,y,z`；预览会话再追加 `#preview:<玩家UUID>` 使模拟结果私有
- 粗筛是**会话级**的一次性阶段（`session.prefilted`），搜索进度才是玩家级

### 编译坑
Paper Brigadier：`Commands.literal(...).requires(pred)` 的 `pred` 参数是 **CommandSourceStack 本身**，
不是 `CommandContext`（`executes` 才是 CommandContext）。写成 `ctx.getSource().getSender()` 会编译失败。

## 2026-10-14（续）JwardChest 设计评审：7 问 + 3 处修正

用户就 TileState/PDC、搜索性能、占位识别、粗筛布局、坐标参数、YAML vs MySQL、JMenu 已知缺陷逐一提问。

### 已修正
1. **坐标参数与补全**（原实现只有准星）：`/jc new [坐标]`、`/jc unbind [坐标]` 改用
   `ArgumentTypes.blockPosition()`（`BlockPositionResolver` → `BlockPosition.blockX/Y/Z`），
   自带 `~` 相对坐标与原版坐标补全，可配合 `/execute positioned` 供命令方块使用。
   `unbind <坐标>` 刻意不要求玩家、且**不检查方块是否为 air**——用于清理「方块已被破坏」的残留绑定。
   `reset preset <代号>` 也加了预设组名补全（`store.groupCodes()`）。
2. **搜索刷新量**（原每 tick 都重建占位物品）：`WardGui.searchingText()` 把显示文本**量化**
   （非紧急阶段只显示整秒，`urgency-seconds` 内才用 0.1s），`WardSearchController.push()` 在
   **文本未变时直接跳过 setItem 与物品构造**。每玩家发包量从 ~10/s 降到 ~1/s（末 2 秒才回到 10/s）。
3. **控制台维度判定**（实测发现的真实偏差）：Paper 里 `CommandSourceStack.getLocation()` 对**控制台
   也返回位置**（主世界 0,0,0），所以原先写的 `loc == null → 全部维度` 永远不成立，
   `reset radius/box` 从控制台执行会被错误地限制在主世界。改为按**执行者类型**判断：
   `ConsoleCommandSender → 全部维度`，玩家/命令方块 → 用执行位置所在维度（`execute in` 生效）。
   同时把维度名加进 `new`/`unbind` 的回执文案，避免「默默按主世界处理」。

### 结论性回答（已告知用户，无需重复取证）
- **不需要 TileState**：绑定写在**区块 PDC**（键含坐标），任意方块都能用，
  因此不存在「方块不支持 PDC」的分支。已核对 paper-api 源码：key 允许 `[a-z0-9_-./]`，
  负坐标的 `bind_-12_64_-30` 合法。
- **搜索任务是「每会话 × 每玩家」一个**（不是全局遍历）；每玩家各自持有一份 Inventory，
  `setItem` 只发给该玩家一人；每 tick 只碰「正在搜索」的那一格。
- **粗筛布局只有一套通用算法**（按宽度水平居中 + 越界裁剪），没有做 per-type 布局表。
- **占位识别**只在交互事件里做（一次 `getItemMeta` + 一次 PDC 读），不参与每 tick；
  真正的问题是「单一信号源」，可选加固见下。
- **选 YAML 而非 MySQL**：写入量小且低频、不能让插件启动依赖 DB 可达
  （`entry.java` 在 `Joyous.database` 初始化失败时会禁用整个插件）、可手改、无 schema 与网络 IO。
  已知弱点：`save()` 仍在主线程同步落盘，且调整数量/权重的按钮是「点一次存一次」。
- **JMenu 那两个坑在结构上被绕开了**：识别信息挂在 **Inventory 对象自身**（自定义 InventoryHolder），
  不是「打开后再写 Map」，所以没有写序竞态；搜索任务每 tick 校验 holder 仍是自己那个会话；
  受保护物品的点击/拖拽全部 fail-closed；即便识别完全失败，容器里也只有空位、占位玻璃板、
  和**已经搜出来的**结果——没有「提前拿到战利品」的路径。

### 待用户拍板的加固项（尚未实现）

- 粗筛的**垂直居中**、以及 per-type 布局表
- `save()` 防抖（置脏 + 1s 延迟 flush），避免连点按钮反复重写文件

## 2026-10-14（续 2）按用户 6 条指令收尾

1. **占位物品改为「custom_model 为主 + custom_data 为来源标记」的双重校验**
   - `custom_data`（PDC `joyous:jc_placeholder`）只负责标识「由 Joyous 产生」；
     资源包识别走 `item_model`
   - `WardGui.isPlaceholder()` = 「PDC 命中 **或** item_model 命中我们配置的占位模型」，
     任一命中都拦住玩家取走占位；`placeholderTag()` 也在 PDC 缺失时用模型反推状态
   - 模型键取值优先级：`placeholder.model.<状态>` → `placeholder.item-model`（单键旧写法）→ 空（不设置）
   - 不带 `:` 的键按 `minecraft:` 命名空间解析（用户当前配置写的是 `joyous_jc_unsearched`，
     即 `minecraft:joyous_jc_unsearched`；要用 joyous 命名空间得写 `joyous:jc_unsearched`——**已提醒用户确认**）
   - `custom_model_data` 若配置则与 item_model **同时**写入（两种识别方式的资源包都能用）
   - 非法模型键（大写/中文）只 warn 不抛，避免整条搜索流程炸掉
2. **粗筛布局**：标准容器（槽位数是 9 的倍数）把 `行×列` 区域**正中心**摆放，垂直用整除向下取整
   （偶数行差 → 偏上）；非标准容器（漏斗/熔炉/酿造台等）不做居中，**从 0 号槽位起顺序铺开**
3. **落盘时机**：`save()` 只改内存并置 dirty，`flush()` 才写文件且无改动时直接返回
   - 统一落盘点：编辑类界面**关闭**时、`/jc new` 与 `/jc unbind` 之后、玩家退出、
     聊天栏输入提交后、模块 onDisable
   - 首次运行的空模板用私有 `writeNow()`（无条件写），否则会被 dirty 判定挡住
4. **刷新率**：确认本来就是配置项 `search.update-interval-ticks`（2=10fps / 4=5fps），补了注释说明
5. **预览 Shift 点击**：`search.open(..., animate)` 新增开关，`animate=false` 时跳过粗筛与动画、
   `revealAll()` 直接摆出全部结果并计入该玩家进度
