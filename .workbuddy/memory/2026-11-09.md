## JwardChest：搜索顺序改为「每玩家环形游标」

问题（用户指出）：`nextSearchSlot` 原来返回「最小的未揭开槽位」。内容共享之后，别人往靠前的空槽
里放东西会把这个玩家的下一格拽回队首 —— 于是 B 可以通过放入物品改变 A 的搜索顺序、拖慢 A 的进度。

改法：
- `WardSession` 把 `Map<UUID, Set<Integer>> revealed` 换成一个 `Progress`：
  `{Set<Integer> revealed; int cursor; boolean prefilted}`。
- `nextSearchSlot` 从 `floorMod(cursor + 1, total)` 开始环形扫描，命中第一个「有物品且我没揭开」的格子；
  `cursor` 只在**真正走完倒计时**时推进（新 API `markSearched`）。
- 记账用的 `markRevealed`（放入物品时标记「他自己知道这一格是什么」、领取回滚时恢复）**不动游标**。
- `put()` 清除所有玩家的该格 revealed，但不动任何人的 cursor → 新东西排在各自这一轮的队尾。
- 顺带修正：`prefilted` 原来整个容器一个布尔值（A 走完粗筛后 B 再也不看粗筛动画），
  改成每玩家一份；`/jc info` 因此不再报「粗筛已过/未过」，只报剩余件数与观看人数。

验证：用等价算法跑了环形用例 —— 0,1,2,5 有物品时顺序为 0→1→2→5→-1；
A 在 slot 2 时 B 往 slot 0 放东西，A 的 next 仍是 5（不是 0），A 搜完 5 后才绕回 0。
编译通过，jar 已部署到 `mcserver/plugins/Joyous-0.3.0.jar`，真机行为待上线确认。

`com.github.streackmc.Joyous.JSell`，14 个类约 4.8k 行；已在 `entry.Models` 注册，config/language 已补。

- 玩家 `/jsell`(`/sell`)：`gui`(6×9 界面)/`hand`/`inv`/`all`；权限 `joyous.jsell.use`（默认所有人，但必须有节点）

  （单价/限购数量/窗口时长/匹配模式/卖出命令/逐件命令/移除/删除），聊天栏输入复用 JwardChest 的做法

  运行时 `jsell_escrow` / `jsell_tx` / `jsell_usage` 三张表（Sdb 原始 SQL + 白名单断言）
- 结算协议：PREPARED → COMMITTED → REFUNDED → PAID → 删除；前两阶段可整单退回，后两阶段按已售处理
- 抗灾：界面内容每次变动同步落库；关界面/断线=取消（退还 + `saveData()`）；崩服=下次上线交付

### 踩到的两个真坑（都已修）

1. **`ItemStack#serialize()` 不能用来做 NBT 比较**：1.21.5+ 它的结构从 `type/meta` 变成
   `id/components`（我在 1.21.11 上用自检打印出来了），而且 `components` 里的值不是普通 Map，
   递归子集比较直接失效。改成「PDC 子集 + Lore 前缀 + 附魔等级 + 其余数据组件逐项相等」。
   另外 `DataComponentTypes.CUSTOM_DATA` 在 1.21.8 API 里根本没暴露 → 按 `type.getKey().getKey()` 判名。
2. **SConfig 的 `put("items.<uuid>.item", …)` 会把 YAML 写坏**：写出 `items: { <uuid>: { <uuid>.item: … } }`
   ——层级和字面键混在一起，读回来找不到。凡是「动态键 + 复合路径」的存档都不能用点号路径，
   改用扁平列表 + 整条 Base64。

### 构建陷阱

VS Code 的 Java 语言服务器会用 ECJ 把「带编译错误的 class」写进 `target/classes`，随后
`mvn package` 的增量编译跳过它 → 运行期出现 `java.lang.Error: Unresolved compilation problems`。
**改完代码一律 `mvn clean package`**（这次就是这么发现 `getType` 根本不存在的）。
