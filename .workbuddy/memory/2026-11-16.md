## 排查「SConfig 嵌套写入」认知偏差（库缺陷 vs Agent 对齐）

用户提出：项目里有些地方正常用深嵌套、有些地方刻意规避，怀疑 Agent 对 StreackLib 的理解有偏差。

### 实测结论（jar 直跑探针，非静态推理）
- 环境：`~/.m2` 里 0.6.1 / 0.6.2 jar（先 `zip -d` 去掉 META-INF 签名，否则 `SecurityException: Invalid signature file digest`）
- **0.6.1 及更早**：`putNested` 用 `getIndexOfNormalDot`（第一个未转义点）当「最后一个点」取叶子名 →
  `a.b.c` → `a: {b: {b.c: v}}`、`a.b.c.d` → `a: {b: {c: {b.c.d: v}}}`；`remove(a.b.c)` 静默无效；
  `putSection("p.q.r")` 同病。**2 段路径正常**。
- **0.6.2 已修**：`splitWithNormalDot` 成为唯一分段权威，叶子取最后一段。实测 2/3/4/5 段
  写→读→reload→读 全一致，`remove`、`putSection` 均正常。
- **0.6.1 里「读」一直是好的**（`getNested` 递归下探）→ 这解释了「为什么有些地方深嵌套一直正常」：
  Restarter 读 `Restarter.autoRestart.while.heapDump.path`（5 段）从来没出过事。
- m2 缓存的 `master-SNAPSHOT`（11-11 构建）**仍是旧坏版本**（`targetMap.put(lastKey, …)`），
  为绕别的缺陷切过去会踩回老坑。
- 仍存的坑（与深度无关）：路径中段是标量时静默退化为「整条路径当顶层字面键」，`isReachable()` 可预判。

### 为什么代码里两种写法并存
- 深写只有一处：`utils/i18n.tr()` 的差量回写 `putString(key, result)`（键深 3~4 段）→ 正是被 0.6.1 写坏的那处。
  现场证据：`mcserver/plugins/Joyous/language.yml` 里 233 个「带点的叶子键」
  （`jwardchest: command: reload: command.reload.done:`），且默认 `writeMode=autosave` →
  这些键永远 miss，每次 `tr()` 都整文件重写一遍。
- 规避的两处：`JwardChest/WardProfile.writeTo`（2026-10-14，0.6.1 时代 → 当时完全正确的止损）、
  `JSell/data/SellEntryStore`（注释写于 11-15，**已在 0.6.2 之后**，理由过期）。
- 结论：不是「Agent 把好库当成坏库」，而是**规避决策没有绑定版本号**——记忆里记的是「无发布版含修复」，
  0.6.2 发版后这句话失效，没人回头核对，注释又把过期结论复述给下一个读者。

## 用户补充的两条项目事实（已写入 MEMORY.md）

- `mcserver/` 是测试服务器目录，非生产环境，**世界/存档/配置随便造随便删都没事**
- `jlogger` 的 varargs 语义：第一个 String 是模板，**末尾 Throwable 不占 `%s`**（`extract()` 先把它摘出去），
  故「参数总个数 = `%s` 个数 + 2」（模板 + 末尾 Throwable）。try/catch 写
  `jlogger.warn("%s：%s", ctx, e.getLocalizedMessage(), e)`；`severe/error` 走真 Throwable 后端，
  `warn/info/debug` 把堆栈拼进消息文本。⚠️ `%s` 多于实参会在 `String.format` 当场抛
  `MissingFormatArgumentException`——日志调用自己崩掉


## 修：JSell 卖出一次后「确认按钮点不动、关界面不退款」（僵尸会话）

现象：第一次出售正常；之后再打开界面，放入物品能看到总价、按钮是亮的，但点确认毫无反应，
按 Esc 关闭也不把物品退回（要重登才由 `deliverPending` 补发）。

根因：`SellSessionManager.active` 里的会话**结算完没人摘掉**。
`SellService.sellGui()` 成功后只做了 `settled(true)` + `drain()`，`JSellSellPage.onDetach()`
看到 `settled()` 就直接 return（本意是不重复退款），于是会话永久留在表里。下次 `/jsell`
的 `sessions.open()` 见到非空就直接复用它 → 拿到一个 `settled=true` 的空会话：
- `confirm()` 首行 `if (session.settled()) return;` → 按钮点了没反应；
- `onDetach()` 首行同样 return → 不 `cancel`，物品既没退回也留着托管行。
这类「已结算还在表里」的会话记为**僵尸会话**。

修法（双保险）：
1. `SellSessionManager.complete(session)`：按实例 `active.remove(uuid, session)` 摘掉结算完的会话
   （用 `remove(key,value)` 免得误删之后新开的会话）；`SellService.sellGui()` 成功路径 `drain()` 后调用。
2. `SellSessionManager.open()`：拿到已有的 `settled()` 会话时**不返回**，先摘掉再新建（兜底，
   防止将来又有谁忘了 complete）。
3. `JSellSellPage.onDetach()`：`settled()` 分支改为调用 `complete()` 再 return（幂等），
   顺带把 `player == null` 的判断提前。

探针（临时，跑完删）：Player 用动态代理只实现 `getUniqueId`，不需要服务端。
验证「complete → 再 open 是新会话且 settled=false」「忘记 complete 时 open 仍兜底」「complete 幂等」。
另确认测试服 `mcserver/.../models/JSell/groups/` 下 `default.yml`、`test1.yml` 各 1 条、
`items.legacy.bak` 已生成——分组存档在真机上是好的，本次问题与会话表有关，与存档无关。

## JSell：分组筛选升级 + 分组设置（展示名 / unit / economy 覆写）

需求：玩家与管理员的分组筛选共用一个「全部组」列表（**Shift+左键**打开）；管理员在列表里**右键**某组进设置页，
可改展示名、unit 名称、economy（命令 + 小数位）；未设置 = 继承全局；`default` 是特殊组，不提供 unit / economy 选项。

- 新增 `SellGroupSettings`（可空字段 = 继承），存在**组文件顶层**：`display` / `unit.name` /
  `economy.commands` / `economy.decimals`，删掉即继承。读取用 `getSection()` 再取子键——
  `getString(key, null)` 分不清「没写」和「写了空」；写入前把三个顶层键整段 `remove` 再刷，避免幽灵字段。
- `default` 组 `canOverride()==false`：setter 直接丢弃 unit/economy，界面也不画那两个格子（只留展示名）。
- 只有设置、没有条目的组也要保留文件并出现在 `groups()`（`SellGroups.groupsOf(entries, extra)`）：
  否则「改过展示名的组在搬空物品后消失」等于配置被静默吃掉。
- 展示名唯一出口 `store.label(group)`：总览 Lore、两处筛选按钮、组列表页都走它；权限节点/文件名/命令参数仍用组名。
- 价格与文案：`CONF.unitName(group)` / `decimals(group)` / `economyCommands(group)` 三个重载，
  取价点（出售页、总览、管理员列表/详情、`/sellset`、流水、`hand*` 占位符）全部改为按条目所属组。
  跨组时回落到全局单位，并在出售界面逐组列出小计（`jsell.gui.info_group_line`）——把两种货币加总是在撒谎。
- 付款：`runCommands` 用 `Payout(commands, unit, decimals)` 当聚合键，**没覆写时所有组共享同一份配置**，
  仍然只发一次钱（拆成多笔会放大任何按次数触发的副作用，例如「卖一次给一把钥匙」）。
- 新界面：`JSellGroupListPage`（双端共用，`admin` 布尔决定是否显示右键编辑与管理信息）、
  `JSellGroupSettingsPage`（3 行，4=展示名、11=unit、13=economy、15=小数位、22=返回）。
  都走 `INSTANT` 压栈 + `ctx.close()` 回退，父页 `onResume` 自动重画，所以选完组立刻生效。
- 语言键：`jsell.group.*`（42 条）、`jsell.input.{display,unit,economy,decimals}_hint`、`jsell.gui.info_group_line`；
  两处 `group_hint` 都补了 Shift 说明。

验证：

   ⚠️ 探针需要先用反射把组名塞进 `SellGroups.REGISTERED`，否则 `register()` 会因 `Joyous.pluginManager == null` 抛 NPE。
