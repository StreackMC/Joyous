# 2026-10-15 JwardChest：数量分布对齐

## 问题
用户问「物品可抽出数量满足什么分布？」——上一轮我把结果组总条数做成了**确定值（Σ上限）**，
只有各品质内部的配额是随机分摊，语义不自洽（既有 min/max 又恒等于 max）。

## 结论（已实现）
凡是「在 下限~上限 之间取一个整数」的地方，统一走新的 `WardDistribution`：

| 位置 | 区间 | 默认分布 |
|---|---|---|
| 结果组总条数 | 各品质下限之和 ~ 上限之和 | uniform（离散均匀） |
| 单条结果的物品数量 | 条目的 最小数量 ~ 最大数量 | uniform（离散均匀） |

- 三档：`uniform` 均匀 / `low` 偏小 / `high` 偏大；`curve` 为曲线指数（仅 low/high，1.0=线性）
- 配置键 `JwardChest.draw.count-distribution|count-curve|amount-distribution|amount-curve`
- **总条数下限强制 ≥1**（容器有格子时），避免"下限没设"时抽出一个空箱子；
  想让某品质「一定有 N 条」就设它的最小抽出数量
- 全 0（不限量）分支不变：按容器容量抽满

## 实现要点（易踩的坑）
`pick()` 用 **`floor(shaped * (span + 1))`** 而不是 `round(shaped * span)`：
后者会让区间**两端各只拿到半个桶**，导致最小/最大值出现概率只有中间值的一半。
实测（6000 次，[1,5]）：uniform → 1208/1210/1210/1195/1177（端点正常 ✓）

## 真机实测（Paper 1.21.11，临时自检块，验完已删）
- uniform [1~5]：1208/1210/1210/1195/1177，均值 2.99
- low(curve=2)：2609/1167/869/730/625，均值 2.27
- high(curve=2)：642/721/853/1125/2659，均值 3.74
- 总条数（下限和 0 / 上限和 10 / uniform，400 次）：1~10 各约 40 次 ✓
- 物品数量（1~5 / uniform）：1220/1172/1193/1166/1249 ✓
- 零异常；`/jc info` 新增一行「数量分布：总条数 uniform，物品数量 uniform」；
  上下限编辑界面与 lore 也显示了分布与区间

## 边界处理
`config.yml` 里仍有用户自己的两处改动（`item-model`、`idle-timeout-seconds`）。
本轮我需要往 config.yml 加 `draw:` 段，采用「**提交后还原工作区**」的做法：
1. 先把「用户改动 + 我的新块」的完整文件备份到 /tmp
2. `git checkout HEAD -- config.yml` 拿到纯净 HEAD 版本
3. 只往里加我的 `draw:` 块 → 暂存 → 提交
4. 再把备份拷回去 → `git status` 里只剩用户的那两处改动
这样既不把用户的改动混进我的提交，也不丢他的工作区内容。
