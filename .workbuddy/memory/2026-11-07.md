### 结论（待修）

**P0/高**
1. **待选物品「取消」无效**：`WardProfile.copySettingsFrom` 对 `entries` 只做 `addAll`（浅拷贝），
   `WardProfileStore.effective()` → `ItemEditorState` 三层共享同一批 `WardItemEntry` 实例；
   权重/数量/品质的修改直接改到 store 里的对象，取消只 `itemWork.remove`。
   且下一次任何 `save(profile)` 都会把"已取消"的改动 `writeTo` 落盘。
   → 修法：`WardItemEntry.copy()`，在 `copySettingsFrom` 里深拷。
2. **运行时容器吞物品**：`WardListener.onClick` 的 RUNTIME/PREVIEW 分支只拦占位物
   （`isOurPlaceholderClick` 在 `!inTop` 时直接 return false），
   所以 shift-click 背包物品、或手持物品点空的顶部槽位、或拖拽到空槽都会被放进自定义 Inventory，
   关闭即整份丢弃、无返还。→ 需拦「所有会把物品放进顶部背包的点击/拖拽」。

**P1/中**
3. `WardSearchController.tickSearch` 槽位越界分支把 `s.current` 置回 -1 → `nextUnrevealed` 返回同一格 →
   每 2 刻空转一次、该格永远搜不出（容器行数/类型变小后必现）。注释说"跳过这一条"但没跳过。
4. `WardEditorGui.MAX_DRAW_SIZE` 是 static final（类首次加载时按当时档位数算），
   而 `maxDrawSlot()`/`handleMaxDrawClick` 用动态的 `maxDrawRows()`；
   `/jc reload` 把档位从 ≤9 改成 ≥10 后，「抽出数量」界面越界写入 → 打不开。
   → 改成非 static 或每次按 `WardRarity.size()` 现算。
5. 改完待选物品后，**已生成的会话不失效**（`ensureGenerated` 只在 `!generated()` 时抽），
   默认空闲回收 3600s，管理员会觉得改动没生效。→ `store.save()` 时 `sessions.removeByProfile(id)`。
6. `/jc reset all|preset|radius|box`、`/jc unbind`、`/jc break` 只从 manager 移除会话，
   不 cancel 正在跑的搜索任务 → 正在看的玩家仍能继续搜完/拿完（reset 对观察者无效）。

**P2/低**
7. 解绑不删 profiles.yml 里的设置段（`ownSettings` 无删除 API），文件与内存长期累积。
8. `WardProfileStore.effective()/own()` 是读路径但有写副作用（未知 UUID 会插入一条默认设置）。
9. `WardGui.isPlaceholder` 只校验 PDC 键 `joyous` **存在**、不校验值；键名过于通用。
10. 编辑界面「保存/取消」后丢方块坐标：`handleItemEditorClick` 里 `Location block = null` 恒空 →
    预览退化为以玩家所在位置建会话。
11. 关闭预览（PREVIEW）不回主编辑界面（不在 `SUBMENUS`）；`onQuit` 也不清预览会话。
12. 无爆炸/活塞/`/setblock` 保护 → 方块被替换后残留"幽灵绑定"（绑定存在区块 PDC）。
13. `/jc info` 没有 `.requires(...)`（其它子命令都有）→ 任何玩家可读容器配置。
14. 死代码：`WardSessionManager.of/removeBlockSessions/get`、`WardProfile.totalDrawCount/addEntry`、
    `WardRarity.defaults`、`WardGui.placeholderTag`。
15. `WardRarity.DEFAULTS` 里 blue 用 `§9`，config.yml 用 `§b`（兜底与正式不一致）。
