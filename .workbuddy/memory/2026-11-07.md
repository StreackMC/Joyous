## 追加复核（用户提问：容器状态为何没保存 / 外来物品的时长与品质）

### 根因：数据模型里没有"容器内容"这一层
- `WardSession.loot` 是抽奖**快照**（只 `fill()` 写一次，`WardSearchController:131`），
  `slots` 只有 `index→槽位`，**没有反向表**（槽→index），`revealed` 只记"揭开过哪几条"。
- 全模块没有任何 `InventoryClickEvent` 回写；`setItem` 全部作用在 `open()` 里新建的那份 Inventory。
- 方块只是"伞"（chunk PDC 存 profile UUID），方块本身没有 Container 实体；session 只在内存。

### 由此产生的真实后果（比"没保存"更重）
1. **无限刷取**：`buildInitial`（`WardSearchController:185`）对 revealed 的结果重新 `setItem(loot.item())`，
   而 `allRevealed` 的提前 return（:93）在它之后 → 搜完一次后每次重开都是满箱，拿走→关闭→重开→再拿。
2. "共享"从未成立：每次 open 新建 Inventory，N 个玩家各拿一份完整结果。
3. 放入的物品无记录，关闭即丢（同"吞物品"）。
4. 重启/空闲 3600s 后 session 消失 → 重抽。

### 修法（若要"共享"）
需补三层：`contents[slot]` 权威内容 + `indexOfSlot` 反向索引 + 取出/放入回写并广播到各 viewer。
架构冲突要记住：搜索动画要求"这格对我什么状态"**私有**，而"箱里有什么"**共享** →
不能改成一个共享 Inventory 大家 open（占位会串台），只能是"共享内容 + 私有视图"。

### 品质的来源（回答"外来物品时长/品质是啥"）
- 品质不在物品上，只在 `session.loot[i].rarity`，靠 `slots[i]` 的**位置映射**关联；
  时长 = `rarity.searchSeconds(amount)`（`WardSearchController:313`）。
- **结果物品零标记**：`WardRoller.loot()` → `entry.display()` 仅 clone+setAmount（`WardItemEntry:61`）；
  带 `joyous` PDC 与 `custom_model_data.strings` 的只有占位玻璃板（`WardGui:269/305`）。
  所以"物品属于插件产出"目前不成立，唯一识别手段是槽位。
- 外来物品三种处理：①不参与搜索直接可见（推荐）②归入 `first()` 兜底档（与最低档结果混淆）
  ③roll 时写 PDC 记 rarity（只是建议值，玩家可搬运复制，槽位仍须为权威）。
- 额外坑：外来物品若落在结果槽，`tickSearch:340` / `buildInitial` 会直接覆盖 → 静默销毁。

## 决策：走 (b) 真·共享箱（用户 21:28 确认）

**关键简化**：不必引入 `ItemStack[] contents`。因为 `loot + slots` 本来就已经是**共享快照**，
只要把"已取走"从「per-player 的隐含行为」提升为 **session 级共享集合 `taken: Set<Integer>`**，
contents 就可以由 `taken.contains(i) ? TAKEN : loot[i].item()` 派生。
→ 改动量从「重写数据模型」降到「加一个集合 + 三态渲染 + 广播 + 持久化」。

核心语义变更：**"搜索揭开"与"领取"分离**（现在 tickSearch 完成 = 物品出现 = 可拿）。
三态（按玩家视角，先查共享 taken 再查私有 revealed）：
`TAKEN`（灰玻璃板，共享） → `HIDDEN`（黑玻璃板/搜索中帧，私有） → `CLAIMABLE`（真实物品）；
非结果槽 = `EMPTY`（air，不可交互）。

配套决策（待用户最终拍板，默认按此实施）：
- 第一阶段 **禁止放入**（RUNTIME 一律 cancel）→ 「外来物品没品质」问题自然消失；
  将来要支持再升级到 `contents[]` 模型。
- 领取方式 **点击即领取**（cancel + `addItem`，余量掉脚下），不做自由拖拽。
- 持久化到 `models/JwardChest/contents.yml`（复用 `WardItemEntry.serialize()` + slots + taken），
  dirty 批量落盘，`unbind`/`break` 时删除。
- 广播：每个 viewer 各有私有 Inventory，对每份各 `setItem` 一次即可
  （服务端 menu 每 tick diff 自动下发，不需手动 updateInventory）。

实施分三批：B1 内存共享（taken/三态/领取/广播）→ B2 持久化+清理 → B3 体验(info/config/日志)+历史 P0/P1。
