## 连接生命周期：从插件生命周期剥离为 公开API + 命令

- 背景：用户已在工作区手写了 `/neonaic bridge status|start|stop` 骨架（`start` 方法未写完），本次补全
- `NeonaicBridge`：调度器/HTTP 客户端改为**随连接创建/销毁**，`start()/stop()/restart()` 可反复调用（stop 后可再 start）
- `NeonaicSubsystem`：`onEnable` 只做装配（注册监听器/占位符/命令），**不再自动建连**；
  新增公开 API `startConnection()` / `stopConnection()` / `restartConnection()` /
  `isConnectionRunning()` / `isPeerReady()` / `connectionMode()`，以及静态 `get()`
- 命令：`/neonaic bridge status|start|stop|restart`（权限 `joyous.commands.neonaic.status`）
- 配置：新增 `connect.auto-connect`（默认 `false`；为 true 时模块启用即连接）
- `onDisable` 只做资源清理（关套接字/注销端点），不代表生命周期负责连接

## 重连语义（关键结论）

- **Joyous 是监听端，不主动重连**；重连是连接发起方 Neonaic 的职责（V1 §10 指数退避）
- 对端断开 → 本端 `read` EOF → 会话 `transportClosed`（未完成请求以 timeout 结清）
  → **accept 循环继续运行** → 对端重拨即被接纳（无需 stop/start）
- 半开连接靠**本端主动发 ping** 发现（UDS 半开不会自己报错）
- HTTP 模式无长连接，"重连"无意义（restart 仅重建客户端对象）
- 写入 `docs/neonaic/PROTOCOL-V2.md` §12（连接生命周期与重连）+ Neonaic 改动概要 §11
