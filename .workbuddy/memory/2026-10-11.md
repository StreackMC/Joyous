## 重连语义（关键结论）

- **Joyous 是监听端，不主动重连**；重连是连接发起方 Neonaic 的职责（V1 §10 指数退避）
- 对端断开 → 本端 `read` EOF → 会话 `transportClosed`（未完成请求以 timeout 结清）
  → **accept 循环继续运行** → 对端重拨即被接纳（无需 stop/start）
- 半开连接靠**本端主动发 ping** 发现（UDS 半开不会自己报错）
- HTTP 模式无长连接，"重连"无意义（restart 仅重建客户端对象）
- 写入 `docs/neonaic/PROTOCOL-V2.md` §12（连接生命周期与重连）+ Neonaic 改动概要 §11

## 2026-10-11（续）JMenu 点击语义答疑 + 顺带发现 3 处缺陷

用户问：点击按钮后会不会重绘菜单？执行命令后菜单会不会关闭？

### 结论（代码为准）
- **Java 版（箱子 GUI）**：`JMenuListener.onInventoryClick` 在 `executeAction` 之前**无条件**
  `player.closeInventory()`（JMenuListener.java:82）→ **点击任意按钮菜单必定先关闭**。
  是否"重绘"只看 action：
  - `menu` → `openMenuFor(param)` 打开指定菜单；**param 填同一路径即等于重绘**
    （会重新逐玩家解析 PAPI、按权限重摆按钮）
  - `cmd`/`op`/`con`/`url`/未知 → 菜单保持关闭，**不重开**
  - 点在玩家自己背包 / 权限不足 → **不关菜单**（`closeInventory` 之前就 return；且无权限按钮本就不显示）
- **基岩版（Floodgate SimpleForm）**：插件不调 close；表单由**客户端**在点按后自动关闭，
  `closedOrInvalidResultHandler` 什么都不做；`menu` 动作＝**再发一张新表单**（这就是基岩的重绘）
- 没有"保持打开"的配置项，也没有自动刷新机制；菜单文件的 tooltip 等仍受缓存 TTL 约束，
  但 `%player_name%` 之类**每次打开都会重新解析**

### 顺带发现（未改，待用户决定）
1. **配置键拼写错误**：`config.yml` 是 `JMenu.cahce_ttl`，代码读 `JMenu.cache_ttl`
   （JMenuMain.java:73）→ 配置值**从未生效**，一直用默认 `1000*60*30` ms。恰因默认值=1800 秒=30 分钟
   与配置意图一致，所以看不出来。
2. **单位不一致**：配置注释写"秒"，值 1800；但代码把该值当**毫秒**用（默认值就是 `1000L*60*30`）。
   即便把键名改对，`1800` 会被当成 1.8 秒。
3. **文档与实现不符**：`JMenu.default.json` 注释称 `action: menu` 的 `param` 留空＝关闭菜单，
   实际 `openMenuFor("")` 因 `isBlank()` 会回退成打开 **`main`** 菜单（`openMenuFor` 里
   `menuPath.isBlank() ? resolvePath("main") : …`）。要关菜单目前只能玩家自己按 Esc。
   （`/jmenu get` 依赖这个"空=main"语义，改代码时别顺手改错边。）
