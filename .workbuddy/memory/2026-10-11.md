# 2026-10-11 工作日志

## Neonaic 模块实现（Joyous ↔ Neonaic 桥接）

### 背景
- `PROTOCOL.md`（在 `Neonai_副本/extensions/joyous/`，该目录被 gitignore）是 Neonaic 侧已实现的**传输层协议**（V1）
- `src/main/resources/models/Neonaic.yml` 是 **Joyous 侧玩法特性配置**，此前仅有空壳 `NeonaicSubsystem.java`
- 用户决策：先设计**协议 V2** → 出 Neonaic 侧改动概要 → 写连接层 → 实现游戏侧；**Neonaic 项目不改动**

### 交付物
1. `docs/neonaic/PROTOCOL-V2.md` — 协议第二版设计（**该目录被 .gitignore，属本地文档，未入库**）
   - 主版本 1→2；握手帧新增 `subname`；新增方法 `chat.publish` / `chat.broadcast` /
     `ai.request` / `identity.bind` / `identity.resolve`；错误码 `not_bound` / `rate_limited`
   - HTTP 模式新增通用端点 `POST /neonai/invoke`（`{id,method,payload}` 信封），UDS 天然对称
2. `docs/neonaic/NEONAIC-REQUIRED-CHANGES.md` — Neonaic 侧改动概要（同样 gitignore）
3. Java 连接层 `Neonaic/bridge/`：
   - `BridgeProtocol` 常量 / `BridgeException` / `FrameCodec`（JSON+LF 增量分帧，容忍粘包/半包/CRLF/空行/坏帧/1MiB 超限）
   - `BridgeSession` 传输无关状态机（握手、请求响应按 id 关联、PING/PONG 心跳）
   - `UdsServer`（Java 21 AF_UNIX `ServerSocketChannel`，本端持有套接字文件、UTF-8 增量解码用 `in.compact()` 保留半字符）
   - `HttpBridgeClient`（`java.net.http`，invoke / command 两种 POST）
   - `NeonaicBridge` 门面（uds/http/auto 选路、出站调用、方法注册）
4. Java 游戏侧 `Neonaic/`：
   - `NeonaicConfig`（读 Neonaic.yml） / `NeonaicPHAPI`（`%joyous_neonaic_name%` / `_subname%`）
   - `chat/ChatMessageRenderer`（`[msg]/[name]/[subname]/[user]` 单遍替换 + PAPI + 颜色 + hover/click）
   - `chat/AiReplyController`（随机触发概率/玩家间隔/全局间隔 + 上下文窗口裁剪）
   - `chat/ChatListener`（AsyncChatEvent：记录上下文 / from-mc 外发 / @触发 / 随机触发）
   - `chat/GroupChatSync`（from-mc→`chat.publish`；`chat.broadcast`→内播；`identity.bind`）
   - `NeonaicCommand`（`/neonaic status|bind|ask` + 按配置的 Bot 名命令）/ `NeonaicSubsystem`（编排 + HTTP 入站 `/neonai/invoke`）
5. `Neonaic.yml` 扩充 `connect.{uds,http,timeout}`；`WebStatusAPI.buildServerStatusData()` 改 public 供 `status.query` 复用
