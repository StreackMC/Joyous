# 2026-11-15

## 修正 @since 虚标（75 个文件）

问题：pom 是 0.4.0、最新 tag 是 0.3.0，但 75 个文件的 Javadoc 写着 `@since 0.6.0/0.7.0/0.8.0/0.9.0`——
这些版本根本不存在（pom 历史只到 0.4.0）。

溯源：`0.6.0` 来自 `1b7dc83 迁移到SConfig`（那是 **StreackLib** 的版本，被当成插件版本）；
`0.7.0` 来自 JwardChest 落地提交、`0.8.0` 来自 JSell 落地提交、`0.9.0` 是我上一轮的三个新类。

判定方法（可复用）：对每个文件 `git log --follow --diff-filter=A` 找创建提交，
再 `git show <commit>:pom.xml` 读当时的版本号 —— 那就是它真正随哪个版本发布。
不能用「文件首次出现在哪个 tag」判断：`952b1ef` 把 JSell 文件挪进子目录，路径变了会误判。

结果：75 处全部改写（0.6.0→0.2.0 ×1；0.7.0→0.3.0 ×18、→0.4.0 ×37；0.8.0→0.3.0 ×12、→0.4.0 ×4；
0.9.0→0.3.0 ×1、→0.4.0 ×2）。现分布：0.0.1(10) / 0.0.2(2) / 0.2.0(6) / 0.3.0(48) / 0.4.0(43)，
全部对应真实版本。旧值（0.0.x/0.2.x/0.3.x）复核过，与创建时的 pom 版本一致，未动。

规则已写进 MEMORY.md：`@since` 只能填已存在 tag 或当前 pom 版本，pom 是唯一版本源。
