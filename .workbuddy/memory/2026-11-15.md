## 修正 @since 虚标（75 个文件）

问题：pom 是 0.4.0、最新 tag 是 0.3.0，但 75 个文件的 Javadoc 写着 `@since 0.6.0/0.7.0/0.8.0/0.9.0`——
这些版本根本不存在（pom 历史只到 0.4.0）。

溯源：`0.6.0` 来自 `1b7dc83 迁移到SConfig`（那是 **StreackLib** 的版本，被当成插件版本）；
`0.7.0` 来自 JwardChest 落地提交、`0.8.0` 来自 JSell 落地提交、`0.9.0` 是我上一轮的三个新类。

判定方法（可复用）：对每个文件 `git log --follow --diff-filter=A` 找创建提交，
再 `git show <commit>:pom.xml` 读当时的版本号 —— 那就是它真正随哪个版本发布。
不能用「文件首次出现在哪个 tag」判断：`952b1ef` 把 JSell 文件挪进子目录，路径变了会误判。

结果：75 处全部改写（0.6.0→0.2.0 ×1；0.7.0→0.3.0 ×18、→0.4.0 ×37；0.8.0→0.3.0 ×12、→0.4.0 ×4；
0.9.0→0.3.0 ×1、→0.4.0 ×2）。现分布：0.0.1(10) / 0.0.2(2) / 0.2.0(6) / 0.3.0(48) / 0.4.0(43)，
全部对应真实版本。旧值（0.0.x/0.2.x/0.3.x）复核过，与创建时的 pom 版本一致，未动。

规则已写进 MEMORY.md：`@since` 只能填已存在 tag 或当前 pom 版本，pom 是唯一版本源。

## 新增：JSell 出售流水（文本账）

问题：JSell 只在控制台 warn 出错、销量写数据库，**没有任何可对账的流水**，而 Entroprix 有
`plugins/Joyous/logs/Entroprix/yyyy-MM/dd.txt`。

- 新增 `utils/AsyncDailyLog`：单线程守护线程排队写、按天切文件（`<root>/yyyy-MM/dd.txt`）、
  每行 flush、`close()` 幂等且先排空队列。刻意**不注册 JVM shutdown hook**（每行已 flush，
  强杀最多丢一行；注册反而在插件重载时留钩子）。
- 新增 `JSell/data/SellLog`：固定列序 `时间 | 动作 | 玩家 | UUID | 分组 | 内容 | 数量 | 金额 | tx`，
  动作为 `SOLD` / `REFUND` / `FAILED`。写入点只有 `SellService.commit()`：
  钱发出后（`markStatus(PAID)` 之后）逐条 `Sale` 记一行，退款记一行，半途异常记 `FAILED`；
  没配数据库的降级路径也记（tx 写 `no-db`）。
- 配置 `JSell.log.enabled`（默认 true）/ `JSell.log.dir`（默认 `logs/JSell`）；
  启动日志会打印「出售流水 logs/JSell」或「已关闭」。
- 为可测性把 `SellLog.sold` 拆出「玩家名 + UUID 字符串」的重载，`SellLog.init` 拆出显式参数版本。

验证（临时自检，12 项全过后删除）：落盘路径 `yyyy-MM/dd.txt`、一 Sale 一行、列序/金额/分组/事务号、
关闭时不落盘、异步 50 行全落且顺序不变、关闭后写入被忽略、`close()` 幂等。
真机正常 `stop` 关服 exit=0，无 `SellLog` 相关异常。

`JSellMain.CONF.unitName()`，不要硬编码可配置的文案。
