# 2026-10-20

## JwardChest：物品模型映射重写（1.21.4+ 模型烘焙）

### 契约
物品上写**两个**组件：

| 组件 | 内容 |
|---|---|
| `item_model` | 配置项 `JwardChest.placeholder.item-model`，**所有占位物品共用这一个键** |
| `custom_model_data.strings` | `[0]` 品质（珍惜度 id；未搜索时用 `placeholder.none-rarity`，默认 `none`）<br>`[1]` 状态（`unsearched` / `searching`） |

资源包侧在 `assets/<ns>/items/<路径>.json` 用一个 `minecraft:select`（`property:
minecraft:custom_model_data`、`index: 0`）按 `strings[0]` 分 case，就能把「档次 × 状态」的贴图矩阵
全部声明在资源包这边；插件不再按状态挑模型键。实际只出现两种组合：`(none, unsearched)` 与
`(<某档>, searching)`，所以最省事的是只按 index 0 分 case（想分层再把 select 套一层）。
语法依据：Minecraft Wiki「物品模型定义」——`minecraft:custom_model_data` 属性读 `strings`，
`index` 指定取第几个；`minecraft:select` 有 `property`/`cases`/`fallback`。

### 代码
- `WardGui.applyModel(meta, rarityArg, state)`：`meta.setItemModel(key)` +
  `meta.getCustomModelDataComponent().setStrings(List.of(rarityArg, state))` +
  `setCustomModelDataComponent(...)`（Bukkit 侧的组件包装，比 `ItemStack.setData` 更贴合现有流程）
- `WardGui.itemModelKey()`：解析单键（带 `:` 按命名空间，不带则 `minecraft:`；非法只 warn）
- `WardGui.modelState(meta)` / `modelStrings(meta)`：组件反查，**两条同时满足**才算我们的占位——
  `item_model` 命中配置键 **且** `strings[1]` 是已知状态（只看模型键分不出状态，只看字符串会误伤别人）
- `WardGui.Frame` 增加 `rarity`：它现在也是「这一格画出来长什么样」的一部分（`strings[0]`），
  缓存键因此更准
- `pane(...)` 去掉 `tag` 参数，改由 `tagOfState(state)` 推出 —— 状态→标记只留一套映射
- CONF：`placeholderItemModel()` / `placeholderNoneRarity()`；
  删掉 `placeholderModel(state)`、`placeholderCustomModelData()`
- 配置：删 `placeholder.model.unsearched/.searching` 与 `custom-model-data`（整数 CMD 那套）
  ⚠️ `item-model` 默认**留空**：没配资源包时若写了键，物品会显示成「缺失模型」的紫黑格

### 真机验证（Paper 1.21.11，临时自检已删）
- 阶段 A（`item-model` 空）：不写任何组件；未搜索靠 PDC 认出，剥掉 PDC 后 false（预期）
- 阶段 B（`item-model: joyous:jc_placeholder`）：
  未搜索 → `item_model=joyous:jc_placeholder`、`strings=[none, unsearched]`
  各档搜索中 → `strings=[<id>, searching]`，**剥掉 PDC 后仍能认出**（isPlaceholder=true，
  tag=jc_placeholder_searching）
- 反例全对：模型不同但字符串相同 → false；模型对但字符串顺序反 → false；普通石头 → false
- 零异常、零 MISSINGNO_TR；线上配置用 `trap` 原样还原

### 踩坑
`local tag="$1" FIFO=/tmp/x LOG=/tmp/$tag.log` 在 `set -u` 下会报 **tag: unbound variable**——
同一条 `local` 里所有参数的**展开先于赋值**，后面的 `$tag` 拿不到前面刚赋的值。拆成多行 `local`。
